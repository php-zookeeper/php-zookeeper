# PHP 8.6 compatibility

Implement issue #72 on feature/php-8.6, retaining PHP 7.0 metadata and all existing PHP versions. The user approved the compatibility scope in chat and requested implementation on a new isolated branch.

## Approach

Replace the four XtOffsetOf uses with standard offsetof and include stddef.h. For PHP >= 8.6, supply PS_CREATE_SID_FUNC(zookeeper) delegating to php_session_create_id(mod_data), and PS_VALIDATE_SID_FUNC(zookeeper) checking a local ZooKeeper path for a nonexpired stored session. Older PHP retains PS_MOD behavior. Keep timestamp updates on the existing write fallback.

Validation must not call read, acquire a session lock, overwrite session->path, or create nodes. Reject invalid or oversized keys, use bounded retries, and distinguish nonexistent/expired records from backend errors. Backend errors must be surfaced rather than silently granting validity. Use the existing read expiry comparison for consistency.

## Alternatives

Only repairing compilation with an always-successful validator does not meet strict-mode acceptance. Unifying session registration and timestamp callbacks across old PHP versions expands behavior changes unnecessarily; defer that redesign.

## Acceptance

Build/load PHP 8.6 with sessions, retain PHP 8.5 tests, and build once without session support. Test write/reopen, regeneration with both delete-old settings, and strict-mode known/unknown/expired/empty sessions. Add PHP 8.6 to the existing ZooKeeper CI matrix. After successful checks, raise package.xml's upper PHP bound to 8.6.99 and verify an exact PEAR-generated tgz from a clean extraction.

## Scope limits

No release/version bump, publication, merge, or push. Issues #73 and #74 remain separate. Diagnose existing ZTS failures independently; do not suppress compiler diagnostics to claim support. ID regeneration's existing path handling changes only if a failing integration test requires it.
